# DeskNest 架构

## 分层

- `app.py` 管理启动、日志和单实例锁。默认数据目录属于当前 Windows 用户。
- `ui` 使用 PySide6 Qt Widgets。卡片由 delegate 绘制，避免为每个项目创建复杂子窗口；图标在会话内缓存。
- `services` 提供只读扫描、Shell 启动和备份用例；扫描使用 QThread，数据库写入在 UI 线程串行执行。
- `storage` 维护 SQLite 单连接。每个整理操作在事务中记录整理前的完整应用数据快照，最多 30 步。
- `windows` 封装桌面位置、开机启动和全局快捷键。

SQLite `user_version=1`。初始旧版数据会补建 history 表，未来版本使用显式迁移。高于当前版本的数据拒绝打开。

## 数据安全

导入记录引用路径；不修改桌面内容。快捷方式由 Windows 直接启动，保留原有参数。

恢复过程：
1. 只读打开备份，验证完整性、版本、所需字段及外键。
2. 使用 SQLite backup API 复制到同目录临时文件。
3. 初始化并读取临时库验证兼容性，清理旧撤销历史。
4. 创建当前库的恢复前备份。
5. 关闭连接，用同目录原子替换提交恢复；失败则原库保留并可重新连接。

恢复和应用编辑都不触及原文件。应用备份不是 Windows 桌面坐标快照，也不是用户文件备份。

## 本地扩展

未来可在 service 中增加手动添加路径、失效引用修复或本地标签，不需要改变 GUI 框架。若加入真实快捷方式移动，必须新增持久化文件操作日志、冲突处理和中断后恢复；不能把文件系统操作当作 SQLite 事务的一部分。

不预建账号、云同步或管理端。
